# 动态广场宽屏右侧栏

日期：2026-08-18  
范围：仅 Web `#/timeline`，视口约 ≥1280px。
模式：Operate。发现 + 两个已有视图开关，不是内容社区。

## Job

宽屏动态页右侧现在是空画布（正文 75ch，外壳不居中）。用这块地方做两件事：

1. 发现：推荐未订阅大V、热门标签。
2. 把「特别关注 / 次要大V」从顶栏挪到右侧，给中间列让出一行。

窄屏和手机不出现此栏，现有筛选条完整保留。

## 布局

- 只渲染在 `#/timeline`，且 `min-width: 1280px`。更窄：不输出右侧 DOM，避免主列骤缩到不可读。
- 主列仍铺满；筛选条与右栏搜索各占同高 64px 顶部槽位。右侧固定约 300px，`position: sticky` 吸在顶栏下；Feed 与第一张右栏卡同顶。
- 不改正文 75ch、不居中整页外壳、不改 768px 底栏时间线。
- 卡片顺序：栏顶搜索 → 特别关注 / 次要大V → 推荐关注 → 热门标签。
- 不把时间线改成 X 式三列居中；空画布用右侧栏填，不用左右留白。

## 特别关注 / 次要大V

- 宽屏：从 `.tl-actions` 挪到右侧栏搜索下方，两枚等宽横排；同一套 `toggleTimelineFav` / `toggleTimelineSecondary`，状态与现开关一致。
- 窄屏：仍在筛选条那一行，行为不变。
- 平台胶囊留在时间线顶。宽屏不出现「筛选」按钮；关键词搜索在右侧栏顶（回车即搜）。
- 时间线不再按分类筛选。标签靠栏里热门标签、帖子标签和角标。

## 推荐关注

- 数据：现有 `GET /api/recommendations`（按订阅人数）。实现时可把 `recommended_kols` 的 limit 略加大，客户端或接口只展示未订阅、最多 4 条。不新做推荐算法。
- 一行：头像、名字、平台或分类、订阅。点名字进 `#/kol/:id`；未订阅态为中性描边「订阅」，成功后原位变为固定宽度的淡蓝「✓ 已订阅」，不立刻补下一名。
- 「✓ 已订阅」悬停或键盘聚焦时显示「退订」；再次点击直接走现有 `DELETE /api/subscriptions/:kol_id`，不弹确认框。请求期间临时禁用，成功后恢复「订阅」并用克制蓝 toast 反馈；失败则保留原状态并显示错误 toast。
- 订阅关系只在请求成功后更新，不做乐观切换；按钮使用固定宽度，状态切换不引起推荐行横向跳动。页面重新加载后仍只推荐未订阅大V。
- 「显示更多」去 `#/search`，不在栏里展开长列表。搜索页进入即复用 `GET /api/catalog` 罗列全部未订阅大V；关键词只在未订阅项中筛选。
- 展开页复用现有大V卡片和订阅动作；订阅成功后该项从列表移除。没有匹配项显示「没有匹配的未订阅大V」，全部订完显示「所有大V都已订阅」。
- 不足 1 条：整张卡片不渲染。

## 热门标签

- 数据：现有 `GET /api/tags` 的 `dynamic_tags`（贴文真实出现过、按频次），最多 8 个胶囊。
- 点击 = 现有 `tlPickTag`，当前 `timelineTag` 在栏里高亮。
- 没有标签：整张卡片不渲染。

## 状态

- 加载：先出栏骨架或等数据再画卡片；失败则藏对应卡片，不弹一串错误。
- 订阅失败：沿用现有 flash / 错误提示。
- 展开页：初次进入先显示加载态；目录请求失败时在列表区显示可恢复的错误，不影响下方申请区。

## 反目标

- 热搜新闻、谁在看、页脚法务链接。关键词搜索在右侧栏顶，不是新热搜体系。
- 不把时间线改成 X 式三列居中。
- 管理员数据源健康（运维页职责）。
- 新推荐接口、新热搜体系。
- 改手机时间线、改 75ch 正文。

## 实现后果

- 前端：`renderTimeline` 在宽屏多一列；CSS 一条 media query；复用订阅与标签筛选。
- 后端：recommendations 只负责右栏前 4 条；展开页直接复用 catalog，无新路由。
- 测试：宽屏才有栏；窄屏筛选条仍有两个开关；展开页无关键词时列出未订阅项，搜索与订阅刷新仍只保留未订阅项。
