# 动态广场宽屏右侧栏

日期：2026-08-18  
范围：仅 Web `#/timeline`，视口约 ≥1120px。  
模式：Operate。发现 + 两个已有视图开关，不是内容社区。

## Job

宽屏动态页右侧现在是空画布（正文 75ch，外壳不居中）。用这块地方做两件事：

1. 发现：推荐未订阅大V、热门标签。
2. 把「特别关注 / 次要大V」从顶栏挪到右侧，给中间列让出一行。

窄屏和手机不出现此栏，现有筛选条完整保留。

## 布局

- 只渲染在 `#/timeline`，且 `min-width: 1120px`。更窄：不输出右侧 DOM。
- 主列仍铺满；右侧固定约 300px，`position: sticky` 吸在筛选条下方。
- 不改正文 75ch、不居中整页外壳、不改 768px 底栏时间线。
- 卡片顺序：特别关注 / 次要大V → 推荐关注 → 热门标签。

## 特别关注 / 次要大V

- 宽屏：从 `.tl-actions` 挪到右侧栏顶部，同一套 `toggleTimelineFav` / `toggleTimelineSecondary`，状态与现开关一致。
- 窄屏：仍在筛选条那一行，行为不变。
- 平台胶囊和「筛选」（关键词 / 分类 / 标签下拉）一律留在时间线顶，不进右侧。

## 推荐关注

- 数据：现有 `GET /api/recommendations`（按订阅人数）。实现时可把 `recommended_kols` 的 limit 略加大，客户端或接口只展示未订阅、最多 4 条。不新做推荐算法。
- 一行：头像、名字、平台或分类、订阅。点名字进 `#/kol/:id`；点订阅走现有 `POST /api/subscriptions`，成功用克制蓝 toast，该行变为「已订阅」，不立刻补下一名。
- 「显示更多」去 `#/search`（或现有订阅广场入口），不在栏里展开长列表。
- 不足 1 条：整张卡片不渲染。

## 热门标签

- 数据：现有 `GET /api/tags` 的 `dynamic_tags`（贴文真实出现过、按频次），最多 8 个胶囊。
- 点击 = 现有 `tlPickTag`，当前 `timelineTag` 在栏里高亮。
- 没有标签：整张卡片不渲染。

## 状态

- 加载：先出栏骨架或等数据再画卡片；失败则藏对应卡片，不弹一串错误。
- 订阅失败：沿用现有 flash / 错误提示。

## 反目标

- 右侧搜索框（时间线筛选里已有关键词；另有搜索大V页）。
- 热搜新闻、谁在看、页脚法务链接。
- 管理员数据源健康（运维页职责）。
- 新推荐接口、新热搜体系。
- 改手机时间线、改 75ch 正文。

## 实现后果

- 前端：`renderTimeline` 在宽屏多一列；CSS 一条 media query；复用订阅与标签筛选。
- 后端：最多给 recommendations 加「排除已订阅 / 多取几条」，可无新路由。
- 测试：宽屏才有栏；窄屏筛选条仍有两个开关；订阅与点标签走原逻辑。
