# 微信小程序战略评估（2026-08）

> 结论先行：**小程序不作为重点投入**。移动端体验以 H5（已完成底部导航 + 响应式）为主，
> 消费入口以「RSS 订阅源 + Bark/TG/飞书推送」为主；小程序仅在「已有企业主体 + ICP 备案域名」
> 时作为加分项，投入一个精简版即可，不做双端功能对齐。

---

## 1. 目标用户是谁

| 用户类型 | 占比 | 设备/习惯 |
| --- | --- | --- |
| 自托管部署者（本项目的核心） | 高 | 有服务器/Unraid/NAS，懂自建，手机浏览器、Telegram、RSS 阅读器都是日常工具 |
| 被邀请的普通用户 | 低 | 用管理员搭好的实例，微信重度用户 |

关键事实：**本项目用户已经在 Telegram / 飞书 / RSS 阅读器生态里**。把消费入口放到微信生态，
对这些用户是「又多一个 App 里的入口」，不是「唯一入口」——价值是增量而非必需。

## 2. 小程序的上线硬门槛（当前状态）

| 门槛 | 说明 | 对自托管用户的影响 |
| --- | --- | --- |
| 主体资质 | 个人主体类目受限（内容/工具类审核严）；企业主体需注册公司或个体户 | 多数自托管者没有企业主体 |
| ICP 备案域名 | `request` 合法域名必须为已备案 HTTPS 域名 | 备案要求服务器在国内；自托管用户大量使用国外 VPS / 家庭内网，直接卡死 |
| 微信公众平台配置 | 需要注册小程序账号 + 配置 appid/secret（已支持 `WECHAT_APP_ID/SECRET`） | 账号本身免费，但绑定到备案域名才有实际用处 |
| 提审 | 每次发版都要审核，个人主体审核更严 | 迭代成本高，与「改完即生效」的 Web 更新节奏冲突 |
| 隐私合规 | 需提交《用户隐私保护指引》（收集 openid 等） | 一次性成本，不高 |

当前 `miniprogram/config.js` 的 `BASE_URL` 默认 localhost、注释也写明「真机/上线需要改成已备案的 HTTPS 域名」——说明这个瓶颈一直存在，只是被"可选功能"的定位掩盖了。

## 3. 小程序能带来什么（真实收益）

- ✅ 微信内免安装触达：适合「被邀请的普通用户」——他们不一定愿意装 Telegram
- ✅ 微信登录：`wx.login` 换 openid，已实现（`app/wechat.py` + 账号密码降级）
- ✅ 订阅消息（一次性订阅）可作为额外提醒通道——**注意：它不是推送通道的替代品**
- ⚠️ 无法替代的核心能力：新帖实时推送仍依赖 TG/飞书/企微/Bark，微信订阅消息是一次性订阅（用户每点一次授权一次），不能做持续推送

## 4. 替代路径现状（已具备）

| 路径 | 状态 | 覆盖人群 |
| --- | --- | --- |
| 移动端 H5 | ✅ 已完成（底部标签栏 + 响应式，v1.5.0），手机浏览器直接用 | 所有人 |
| RSS 订阅源 | ✅ 刚上线（`/api/feed/<token>.xml`） | 任意 RSS 阅读器用户 |
| Bark（iOS） | ✅ 刚上线 | iPhone 用户 |
| Telegram / 飞书 / 企业微信 | ✅ 原有 | 主力 |

结论：**手机端的使用路径已经完整**，且都不依赖备案域名（RSS/Bark 只要有公网入口或内网地址即可）。
小程序是「锦上添花」，不是「补短板」。

## 5. 建议与决策路径

### 推荐方案（当前阶段）
1. **主推 H5 + RSS + Bark/TG/飞书**，继续打磨移动端 Web 体验；
2. **小程序定位为"可选加分项"**：README 保持「可选」表述，不做双端功能对齐（Web 新增的关键词/RSS/Bark 设置，小程序不强制同步）；
3. 不主动引导用户部署小程序，避免把「部署复杂度 + 合规成本」转嫁给自托管者。

### 何时值得做小程序（触发条件）
- 管理员已有**企业主体 + 已备案 HTTPS 域名**（能过 `request` 合法域名校验）；
- 且实际存在一批**不用 Telegram/飞书、只用微信**的普通用户。

### 如果要做（最小可行版）
只保留 3 个页面：**订阅广场（index）+ 我的订阅（mysubs）+ 推送设置（settings）**，去掉 timeline/search/kol/me/login 等冗余页（现有 miniprogram 8 个页面可裁剪）：
- 登录走微信 openid 自动建号（已实现）
- 推送设置只做「绑定码同步 + 状态展示」，不重复实现 Web 的完整表单
- 发版走「一次性提审大版本」，日常小改动仍以 Web 为准

### 不建议做的事
- ❌ 为小程序做「实时推送」通道（微信订阅消息不能替代现有推送管线）
- ❌ 双端功能逐一对齐（维护成本翻倍，用户收益趋近于零）
- ❌ 为小程序专门申请企业资质（成本 >> 收益）
